# DOCUMENTO MESTRE DO PROJETO MIKAON

> Documento oficial do projeto.
>
> Este documento é a principal fonte de conhecimento do sistema.
> Nenhuma decisão importante deverá permanecer apenas em conversas.
> Toda alteração de arquitetura, regra de negócio ou experiência do usuário deverá ser registrada aqui ou em um dos documentos relacionados.

---

# Objetivo

Desenvolver o MikaON como uma plataforma SaaS de nível internacional, inicialmente utilizada pela MiKATECH e preparada para atender milhares de empresas.

O sistema deverá integrar:

- ERP
- CRM
- PDV
- Financeiro
- Estoque
- Compras
- Ordem de Serviço
- Produção
- Agenda
- Relatórios
- Dashboards
- IA
- Aplicativo Mobile
- Página Pública
- API Pública

---

# Princípios do Projeto

Toda decisão deverá priorizar:

- simplicidade
- estabilidade
- performance
- escalabilidade
- arquitetura limpa
- experiência do usuário
- facilidade de manutenção
- reutilização de componentes

Nunca sacrificar arquitetura por velocidade.

---

# Arquitetura

O sistema seguirá arquitetura modular.

Cada módulo deverá possuir baixo acoplamento.

Sempre reutilizar componentes.

Nunca duplicar regras de negócio.

# Fluxo Oficial

Toda Sprint seguirá obrigatoriamente:

1. Ler este Documento Mestre.
2. Ler as regras do módulo.
3. Analisar impactos.
4. Planejar implementação.
5. Desenvolver.
6. Executar testes.
7. Atualizar documentação.
8. Publicar.

---

# Regras Permanentes

Nunca quebrar funcionalidades existentes.

Nunca remover regras de negócio sem autorização.

Nunca alterar banco sem necessidade.

Nunca duplicar código.

Sempre reutilizar componentes.

Sempre corrigir TypeScript.

Sempre corrigir ESLint.

Sempre entregar build funcionando.

Sempre listar arquivos alterados.

Sempre explicar rapidamente a alteração.

Sempre informar como testar.
