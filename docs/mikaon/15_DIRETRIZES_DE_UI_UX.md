# DIRETRIZES OFICIAIS DE UI/UX DO MIKAON

> Documento oficial de Interface (UI) e Experiência do Usuário (UX).
>
> Toda tela do MikaON deverá seguir estas diretrizes. Nenhuma implementação visual deverá ser realizada apenas por preferência estética.

---

# Objetivo

Construir uma interface profissional, moderna, rápida e altamente produtiva.

O MikaON será utilizado durante muitas horas por dia por operadores, vendedores, caixas e administradores.

Cada decisão visual deverá reduzir cliques, acelerar operações e diminuir erros.

---

# Filosofia

O MikaON NÃO será:

- um sistema cheio de efeitos visuais;
- um sistema com grandes áreas vazias;
- um sistema com ícones exagerados;
- um sistema difícil de operar.

O MikaON deverá transmitir sensação de software comercial profissional.

---

# Princípios

Toda tela deverá priorizar:

- produtividade;
- simplicidade;
- consistência;
- velocidade;
- legibilidade;
- ergonomia.

Sempre priorizar produtividade antes de estética.

---

# Layout

Toda tela deverá possuir:

- alinhamento consistente;
- espaçamentos uniformes;
- componentes padronizados;
- boa utilização da área útil;
- poucas quebras visuais.

Evitar grandes espaços em branco.

---

# Componentes

Preferências oficiais:

Campos compactos.

Botões médios.

Ícones discretos.

Bordas suaves.

Poucas sombras.

Poucas animações.

---

# Tipografia

Utilizar poucos tamanhos de fonte.

Prioridade:

- leitura rápida;
- hierarquia clara;
- contraste adequado.

Nunca aumentar fontes apenas para preencher espaço.

---

# Botões

Botões deverão:

- possuir tamanho consistente;
- manter o mesmo padrão em todo o sistema;
- utilizar cores apenas quando necessário.

Botão principal:

Sempre em destaque.

Botões secundários:

Visual discreto.

---

# Ícones

Os ícones deverão representar ações.

Nunca utilizar ícones apenas como decoração.

Ícones grandes somente quando houver justificativa funcional.

---

# Menus

Os menus deverão:

- abrir rapidamente;
- ocupar pouco espaço;
- permitir operação por teclado;
- manter organização consistente.

---

# Dashboards

Os dashboards deverão responder rapidamente às seguintes perguntas:

- Como está o negócio hoje?
- O que precisa de atenção?
- Quem está vendendo mais?
- Quais indicadores mudaram?

Evitar excesso de gráficos.

---

# Listagens

As tabelas deverão apresentar o maior número possível de informações sem comprometer a leitura.

Prioridades:

- filtros rápidos;
- ordenação;
- paginação;
- ações discretas.

---

# Formulários

Campos relacionados deverão permanecer agrupados.

Fluxo de preenchimento:

Esquerda

↓

Direita

↓

Cima

↓

Baixo

Sempre respeitando a ordem natural de leitura.

---

# Experiência do Operador

Todo operador deverá conseguir utilizar o sistema quase exclusivamente pelo teclado.

Cada clique economizado representa ganho operacional.

---

# Diretrizes do PDV

Fluxo oficial:

Operador

↓

Cliente

↓

Produto

↓

Carrinho

↓

Pagamento

↓

Cupom

Nenhuma alteração poderá quebrar este fluxo.

---

# Pesquisa de Produtos

Pesquisa em tempo real.

Busca por:

- nome;
- SKU;
- código;
- GTIN.

Após adicionar:

- limpar pesquisa;
- retornar foco automaticamente.

---

# Carrinho

Diretrizes oficiais:

Cada produto deverá ocupar apenas uma linha.

Exibir apenas:

- nome;
- quantidade;
- valor da linha;
- controles (+ / -);
- remover.

Nunca utilizar:

- imagens grandes;
- cartões altos;
- excesso de textos.

Objetivo:

Exibir o maior número possível de itens sem necessidade de rolagem.

---

# Pagamentos

A coluna de pagamento deverá permanecer estável.

Nunca alterar altura dos cartões conforme a combinação das formas de pagamento.

Todos os campos deverão permanecer alinhados.

---

# Cupom

Após concluir a venda:

Abrir modal contendo:

- visualização do cupom;
- imprimir;
- salvar PDF;
- enviar por WhatsApp;
- fechar.

Nunca imprimir automaticamente.

---

# Responsividade

Prioridade oficial:

1. Desktop Comercial

2. Notebook

3. Tablet

4. Mobile

O sistema deverá adaptar-se sem desperdício de espaço.

---

# Referências Utilizadas

Durante o desenvolvimento foram analisados:

- ERP atualmente utilizado pela MiKATECH;
- PDV atualmente utilizado pela MiKATECH;
- diversos sistemas comerciais nacionais.

As referências servem para ergonomia e fluxo operacional.

Nunca copiar identidade visual.

---

# Evolução Contínua

Todo print, vídeo ou referência analisada deverá ser registrada.

Sempre documentar:

- ponto positivo;
- ponto negativo;
- decisão adotada.

---

# Regra Permanente

Nenhuma alteração visual significativa poderá ser aprovada sem melhorar pelo menos um dos itens abaixo:

- produtividade;
- ergonomia;
- velocidade;
- legibilidade;
- aproveitamento da tela.

Caso contrário, a alteração deverá ser rejeitada.

---

# Objetivo Final

Construir uma interface consistente, moderna e altamente produtiva, tornando o MikaON um ERP/CRM/PDV de padrão internacional, focado na experiência real de operação.
---

# Diretriz complementar para Produtos/Estoque

Produtos/Estoque devem seguir:

- pesquisa fixa no topo;
- filtros compactos;
- tabela compacta;
- painel lateral ou modal para edicao;
- alta densidade de informacao sem cards altos.
