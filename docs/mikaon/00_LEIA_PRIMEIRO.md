Antes de planejar, implementar ou revisar qualquer Sprint:

1. Ler este arquivo.
2. Ler `01_DOCUMENTO_MESTRE.md`.
3. Ler `09_DECISOES_TECNICAS.md`.
4. Ler o documento específico do módulo que será alterado.
5. Ler `07_ROADMAP_OFICIAL.md`.
6. Verificar impactos, dependências e compatibilidade.
7. Somente depois iniciar a Sprint.

## Formato obrigatório das Sprints

Toda Sprint deve conter apenas:

- Objetivo
- Arquivos envolvidos
- Estratégia
- Implementação
- Testes
- Resultado esperado

## Regras permanentes

- Nunca quebrar funcionalidades existentes.
- Nunca alterar regras de negócio sem autorização.
- Nunca apagar código sem necessidade comprovada.
- Nunca duplicar código.
- Sempre reutilizar componentes e serviços existentes.
- Sempre manter compatibilidade.
- Sempre corrigir erros de TypeScript.
- Sempre corrigir erros relevantes de ESLint.
- Sempre executar build.
- Sempre informar arquivos alterados.
- Sempre informar como testar.
- Sempre atualizar a documentação quando houver decisão permanente.
